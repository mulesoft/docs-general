= Scanning Multiple Accounts and Environments
:keywords: scanners, multi-account scan, cross-account scanning, auto-discovery, amazon bedrock, microsoft copilot studio, microsoft foundry, azure ai foundry, power platform environments, azure subscriptions

A single scanner can discover agents across more than one account in a provider instead of only the account, environment, or project its credential points to. Use a multi-account scan when your organization spreads agents across many AWS accounts, Power Platform environments, or Azure subscriptions and you want one scanner to keep the *Portfolio* catalogs current for all of them.

What counts as an account depends on the provider:

[cols="1,2",options="header"]
|===
| Provider
| Scanned Unit

| Amazon Bedrock
| AWS accounts, in one or more AWS regions

| Microsoft Copilot Studio
| Power Platform environments

| Microsoft Foundry
| Azure subscriptions, and the Foundry projects in them
|===

== Before You Begin

Before getting started, make sure you have:

* Exchange Administrator permission.
* Access to, and active context in, the business group where you want to add the scanner.
* Permission in the provider to create or update the roles, app registrations, or role assignments described for your provider in this topic.

For the single-account prerequisites for each provider, see xref:exp-scanners-prerequisites-reference.adoc[].

== How Multi-Account Scans Work

You choose the scan scope when you add the scanner:

* *Specific targets*
+
You list the accounts, environments, or projects to scan. The scanner scans only those targets.
* *Auto-discovery*
+
You leave the target list empty. The scanner finds every account, environment, or subscription its credential can access, then tries to list agents in each one.

Auto-discovery attempts every target that the credential can see, including targets where it isn't authorized to read agents. If your credential can see many targets but reads agents in only a few, scans take longer. To keep scans fast, list specific targets, or limit what the credential can see in the provider.

=== Skipped Targets and Partial Scans

If the scanner can't access a target, it skips that target and continues with the rest:

* When some targets succeed and others fail, the scan completes as partial. Services discovered earlier in the skipped targets stay in *Portfolio*. The scanner doesn't remove services it couldn't confirm during the run.
* When every target fails with a permission error, the scan fails.
* The scanner retries targets that return rate-limiting errors. It doesn't retry targets that return permission errors, because those errors don't resolve until you fix the permissions in the provider.

To find skipped targets, check the scan's *Activity Log*. For more information, see xref:exp-scanners-view-details.adoc[].

== Scan Multiple AWS Accounts for Amazon Bedrock

A multi-account scan for Amazon Bedrock uses a hub-and-spoke model of AWS Identity and Access Management (IAM) roles:

* The *hub role* lives in one AWS account. The scanner's credentials assume the hub role.
* A *spoke role* with the same name lives in each AWS account you want to scan. The hub role assumes the spoke role in each account to read Bedrock agents.
* An *external ID* on each spoke role's trust policy makes sure only your scanner can assume it.

=== Configure the Scanner

. From *Platform* > *Providers*, select *Amazon*.
. In *Connect to a Provider*, under *Platform*, select *Amazon Bedrock*.
. Under *Scan type*, select *Multi-account scan*.
. Under *Multi-account scan details*, enter the role details:
* *HUB role ARN*: The Amazon Resource Name (ARN) of the hub role, for example, `arn:aws:iam::123456789012:role/HubRoleName`.
* *Spoke role name*: The name of the spoke role you created in each target account.
* *External ID*: The external ID you set in the spoke role trust policies.
. Choose the accounts to scan in *Account IDs*:
* To scan specific accounts, enter each 12-digit AWS account ID and press Enter.
* To use auto-discovery, leave the field empty.
. Choose the regions to scan in *Target regions*:
* To scan specific regions, select one or more regions.
* To scan only the region you selected in the *AWS Region* field, leave the field empty.
. Enter the connection credentials, test the connection, and finish the scanner setup as you do for a single-account scanner.

== Scan Multiple Power Platform Environments for Microsoft Copilot Studio

A Copilot Studio scanner uses one app registration across all the environments it scans. It requests a separate token for each environment's Dataverse URL, so the app must be set up in every environment you want to scan.

=== Set Up the App in Each Environment

. Make sure the app registration can list Power Platform environments in your tenant.
+

. In each environment you want to scan, add the app as an Application User and assign it the Copilot Studio Scanner role.
+
If the app isn't an Application User in an environment, the scanner skips that environment.

=== Configure the Scanner

. Create and authorize the connection by using the *OAuth* authentication scheme, as described in xref:exp-scanners-add-from-providers.adoc#microsoft-copilot-studio-scanner-oauth-authorization[Microsoft Copilot Studio Scanner OAuth Authorization].
. Choose the environments to scan in *Scope*:
* To scan one environment, enter its Dataverse environment URL.
* To use auto-discovery, leave the field empty.

== Scan Multiple Azure Subscriptions for Microsoft Foundry

A Foundry scanner uses one service principal across all the subscriptions it scans. With auto-discovery, the scanner lists the subscriptions the service principal can access, the Azure AI Services and Azure OpenAI resources in each subscription, and the projects in each resource, then lists agents in each project.

=== Set Up Access in Azure

. Assign the service principal the Reader role on each subscription you want to scan.
+
The scanner discovers only subscriptions where the service principal has a role assignment. If it finds no enabled subscriptions, the scan reports a partial failure and asks you to check the Reader role.
. Assign the service principal the Azure AI Developer role on each Foundry project you want to scan.
