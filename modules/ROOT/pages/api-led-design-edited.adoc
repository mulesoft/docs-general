= Step 2. Design an API Specification

In this step, you'll use MuleSoft Vibes to create an API specification by describing what you want in plain language. No code is required.

To design an API, assess the purpose and requirements:

* Identify the type of API: Is it a simple API, part of an integration, or part of a backend system?
* Understand the data flows: one-way, two-way, or more.
* Explore the security requirements.

After you define the scope and flow of your integration project,
define an API specification in link:https://raml.org/[RAML] or link:https://www.openapis.org/[OAS].
Then, in later steps, you'll use the API specification to quickly develop an API.

== API Specifications and APIs

An API is a published interface to a resource that anyone with the correct permissions and a properly structured request can access.

An API specification details the functional and expected behavior of an API,
as well as the fundamental design philosophy and supported data types.
It contains both documentation and API definitions to create a contract that people and software can read.

MuleSoft provides tools that make it easy to create an API specification that you can then share with your team, your customers, or the general public. Using an API specification increases adoption and shortens project completion time.

== Step 2.1: Explore Existing API Specifications

If you look at existing API specifications before writing your own,
you can learn how other people have approached situations similar to yours.
You can also check whether an API specification with the same objectives isn't already in development, and reuse it if appropriate.

Looking for an API specification that already does what you need is easy:

* Look at the public Anypoint Exchange, which is a portal hosted by MuleSoft that contains API specifications, connectors, and other assets that you can download and use.

== Step 2.2: Access Anypoint Code Builder

. Open the desktop IDE (VS Code) with Anypoint Code Builder installed.

. In the activity bar of the IDE, click the image:icon-ms-logo.png["",20,20] (*Anypoint Code Builder*) icon.

== Step 2.3: Generate Your API Spec with MuleSoft Vibes

. Open MuleSoft Vibes from the toolbar or from the *Build Your Ecosystem with AI* card in the canvas.

. Type this prompt in the chat:
+
[source,text]
----
Create an OAS 3.0 API specification called "hello-world-api" with a GET endpoint at /greeting that returns a simple JSON response with a message field containing "Hello, World!"
----

. Press Enter to send.
+
MuleSoft Vibes generates your API specification in about 10 seconds.

. Review the generated spec in the response. It should include:
+
* An API title and version
* A GET endpoint at `/greeting`
* A 200 response with a JSON schema

. Click *Create Project* in the MuleSoft Vibes response.

. Select your home directory as the project location.

. Anypoint Code Builder creates the project and opens `hello-world-api.yaml`.

== Step 2.4: Review Your API Specification

. In the editor, review the generated specification:
+
[source,yaml]
----
openapi: 3.0.0
info:
  title: hello-world-api
  version: 1.0.0
paths:
  /greeting: <1>
    get:
      responses: <2>
        '200':
          description: Success
          content:
            application/json:
              schema:
                type: object
                properties:
                  message: <3>
                    type: string
                    example: "Hello, World!"
----
<1> The endpoint path for the API. Clients send GET requests to `/greeting`.
<2> Defines the possible HTTP responses this endpoint returns.
<3> The JSON response property that contains the greeting message.

== Step 2.5: Test with the Mocking Service

Use the Mocking Service in the API Console to check the request and response that you configured in your API spec.

. In Anypoint Code Builder, open the spec for your API project (`hello-world-api.yaml`).

. Click the image:icon-api-console.png["",14,14] (*API Console*) icon in the editor toolbar.
+
The API Console displays your spec.

. In the API Console, expand the *GET* method for the `/greeting` resource.

. Click *Try It*.

. Click *Send*.

. Verify that API Console returns the response you defined:
+
[source,json]
----
{
  "message": "Hello, World!"
}
----

Congratulations! You've designed an API without writing any code.
