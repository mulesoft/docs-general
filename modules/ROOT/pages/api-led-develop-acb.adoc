= Step 3. Develop the API

Now that you've created an API specification, you'll turn it into a working Mule application. Anypoint Code Builder includes an embedded Mule runtime for local testing. Later, you'll deploy your application to xref:cloudhub-2::ch2-deploy.adoc[CloudHub 2.0], where it runs on Mule runtime in the cloud.

== Step 3.1: Create the Implementation Project

. Open your API specification file in the editor, then click the image:icon-implement-api.png["",15,15] (*Implement this local API*) icon in the activity bar.
+
[NOTE]
The icon and command are only available when your API spec file is open and active in the editor.
+
Alternatively, open the Command Palette and select `MuleSoft: Implement this Local API`.
+
.Show me how
[%collapsible]
====
* Use the keyboard shortcuts:
** Mac: Cmd+Shift+p
** Windows: Ctrl+Shift+p
* In the desktop IDE, select *View* > *Command Palette*.
====
+
[IMPORTANT]
Do not select `MuleSoft: Implement an API Specification`. That command is for specs published to Anypoint Exchange, not local specs.

. At the prompt, click *OK*:
+
image::api-tutorial-implement-local-api-prompt.png["Prompt: We'll create a workspace to keep your API specification and Mule project in sync."]

. Navigate to a directory for your new project, and click *Save*.
+
[IMPORTANT]
--
Do not accept the default location. Save your `.code-workspace` file in a directory outside of your project folder, not within your API spec folder.
--

. When prompted, provide project configuration details:
.. Provide a name for your Mule project, for example, `hello-world-impl`.
.. Navigate to a folder for your Mule project, and click *Select target folder*.
.. Select a Mule runtime version for the project.
.. Select a Java version for the project.
+
Anypoint Code Builder scaffolds your local API specification into a new Mule project. Both the API spec and the Mule project open in your IDE.

. In the Explorer view, navigate to `hello-world-impl/src/main/mule/` and open `hello-world-impl.xml`.
+
This is the Mule configuration XML. This file contains your flows, HTTP Listener, and APIkit Router. The canvas opens automatically when you open it. 

== Step 3.2: Understand the Scaffolded Structure

The canvas shows your scaffolded flows, including: 
+
* *hello-world-api-main*
+
HTTP Listener that receives requests on port 8081
* *get:\greeting:hello-world-api-config* 
+
Your GET endpoint implementation
* Error handling flows

. Click the *Listener* component, then the *Edit Connection* icon (image:icon-gear.png["",15,15]) to review the connection configuration, including:
+
* *Path*: `/api/*` (receives all API requests)
* *Host*: `0.0.0.0` (listens to all interfaces)
* *Port*: `8081` (local development port)

== Step 3.3: Implement the Hello World Logic

Now add the logic to return your greeting.

. Navigate to the *get:\greeting:hello-world-api-config* flow in the canvas.
+
The flow contains a Logger component by default. You'll add a Transform component after it to return your greeting.

. Click the image:icon-plus.png["",15,15] (*Add component*) icon after the Logger component in the flow.

. In the *Add Component* panel, search for `Transform` and select *Transform* from the results.

. Click the *Transform* component to open the DataWeave editor.

. In the DataWeave editor that opens, replace the default script with:
+
[source,dataweave]
----
%dw 2.0
output application/json
---
{
  message: "Hello, " ++ attributes.queryParams.name ++ "!"
}
----
+
This DataWeave script reads the `name` query parameter and returns a personalized greeting.

. Save your changes (Cmd+S on Mac, Ctrl+S on Windows/Linux).

That's it! Your API is implemented and ready to test.

== What Just Happened?

You used these components to implement your API:

* *Scaffolding*
+
Anypoint Code Builder generated the project structure from your specification.
* *HTTP Listener*
+
Receives incoming HTTP requests on port 8081.
* *APIkit Router*
+
Routes requests to the correct endpoint flow.
* *DataWeave*
+
MuleSoft's transformation language for creating responses.
