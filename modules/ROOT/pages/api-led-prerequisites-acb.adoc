= Step 1. Prerequisites for Building an API-Led Solution

Set up your environment before starting the tutorial. You need an Anypoint Platform account, Anypoint Code Builder, and a REST client such as Postman. Specific permissions are also required for deployment and, optionally, for AI-assisted API design.

* Username and password for your Anypoint Platform organization. If you don't have Anypoint Platform yet, create a Trial organization on Anypoint Platform.
+
link:https://anypoint.mulesoft.com/login/#/signup["Create a Trial organization^", role="button-primary"]

* xref:anypoint-code-builder::start-acb-desktop.adoc[Set up Anypoint Code Builder]. 
* To test REST requests, obtain a client such as Advanced REST Client or Postman if you don't already have one. This tutorial uses Postman.
+
link:https://www.postman.com/downloads/["Install Postman^", role="button-primary"]
+
Depending on your platform, you might need to install a different client.

* Required permissions:
** *Anypoint Code Builder Developer*
+
Allows API specification creation
** *Exchange Contributor*
+
Enables publishing assets to Exchange
** *Create Applications*
+
Allows deployment of applications to CloudHub 2.0

* Optional permissions (for MuleSoft Vibes AI features):
** *Mule Developer Generative AI User*
+
Enables MuleSoft Vibes features for AI-generated API specifications. If you don't have this permission, you can still complete the tutorial by manually creating your API specification.
+
*MuleSoft Vibes* requires Agentforce to be enabled in Access Management. See xref:access-management::enabling-agentforce.adoc[].

== CloudHub 2.0 Setup

For CloudHub 2.0 deployments, you need:

* A CloudHub 2.0 Shared Space in your organization. Anypoint Platform trial accounts include a default Shared Space.
+
See xref:cloudhub-2::ch2-shared-space-about.adoc[About Shared Spaces].

* At least one environment (such as Sandbox or Development) configured for CloudHub 2.0 deployments.
+
See xref:cloudhub-2::ch2-environments-about.adoc[About Environments].
