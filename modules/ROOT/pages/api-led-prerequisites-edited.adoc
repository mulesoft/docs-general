== Tutorial Scenario: Order Status System

In this tutorial, you'll build three APIs that work together to provide order status information to customers:

*System Layer: Order Database API*

* Provides direct access to the orders database
* Returns order details, shipping information, and status
* Used by internal applications and Process APIs

*Process Layer: Order Processing API*

* Validates order IDs and checks permissions
* Enriches order data with calculated fields (estimated delivery, status descriptions)
* Aggregates data from multiple System APIs

*Experience Layer: Customer Order Status API*

* Optimized for mobile and web applications
* Returns only customer-relevant information
* Provides friendly error messages and status descriptions

This three-layer architecture demonstrates how API-led connectivity:

* Enables reuse (multiple apps consume the same Process API)
* Supports change (modify business logic without changing Experience APIs)
* Accelerates development (new channels can quickly build on existing APIs)
